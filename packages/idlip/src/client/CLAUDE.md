# client

- The loader (`loader/` with its static imports) has a 4096 B gzip budget (contract) with no optional features, and the e2e test `loaderBudget` holds the todo build to 3900 B. The budget is the loader with every flag off, not with every feature on. Code that only some apps use goes behind a `HAS_*` flag from `features.ts`. Why: every page pays for the loader before the first click.
- A new flag takes three edits: `declare const __IDLIP_HAS_NAME__` and `export const HAS_NAME` in `features.ts`, one line in `DETECTORS` in `../vite/features.ts`, and `if (HAS_NAME)` around the code. Why: the bundler can fold the branch only when the test is that exact form.
- A flag name must not appear in other code or in a string. Why: the plugin replaces the text.
- A chunk may import from `idlip/client` only what the loader already holds, and `idlip/helpers` imports only from `idlip/client`. Why: a chunk import that is not in the loader costs another round trip on the first click.
- The loader loads the `helpers` URL of a state's chunk map with the handler and binding chunks of an event (`getUpdate` in `loader/resume.ts`). Why: chunks import the shared helpers module, and asked for only as an import of a chunk it would cost a second round trip. Cost: +28 B gzip on the todo loader. Putting the helpers in the loader instead measured 4681 B on the todo loader, over the 4096 B budget, and the todo app uses every one of them, so no flag could drop them.
- A failed helpers fetch needs no reload in Chromium. A chunk whose static import of the helpers was waiting on the failed fetch fails with it, and the next event asks for the chunk under a new URL (`#<n>`). Chromium keeps no failed module fetch, so that chunk's import fetches the helpers again and the patch catches up (e2e `todo.spec.ts`, "a helpers module that fails to load once"). Why: a static import cannot take the retry fragment, so recovery depends on the browser fetching again. Firefox and Safari are not tested.
- Patches run one at a time: `patchAll` awaits each unit, and the `added` set of `patch/blocks.ts` (the blocks the running patch added, behind `HAS_INNER_LISTS`) is cleared when a patch starts and when it ends. Why: a second patch running at the same time would clear or read the first one's set.
- Tasks run through `runTask(host, task)` in `tasks/run.ts`. Do not add another path for an awaited call. Why: `apply` and the settle order depend on one.
- Flag-on cost, gzip -9 over the todo loader: `HAS_TASKS` +274 B, `HAS_KEYED` +124 B, `HAS_REFS` +550 B, `HAS_CHILDREN` +794 B, `HAS_SUBS` +937 B, `HAS_HEAD` +307 B, `HAS_ERRORS` with `HAS_RETRY` +635 B (`HAS_RETRY` alone +16 B), `HAS_SKEW` +60 B (plugin option, default on), `HAS_DYNAMIC` +122 B, `HAS_KEY_FN` +24 B, `HAS_INNER_LISTS` +39 B. Why: a change that grows one of them shows up against this list. Update the line when you move a number. `HAS_CHILDREN`, `HAS_ERRORS` and `HAS_INNER_LISTS` measured by `cloned-templates-all` over a 4026 B todo loader; the rest are older.
- Put a field or branch that one feature reads behind `...(HAS_X && { field })` or `if (HAS_X)`. Why: a plain field survives dead-code elimination, and a `Reflect.apply` of a union costs about 9 B a call over a typed call.
- Put code that only one feature needs in its own module with one call site behind its flag. Why: an unreferenced module drops out of the bundle (`head.ts`, `nesting.ts`, `errors.ts`).
- Reach `innerHTML` only through `parseHtml`. Why: it holds the one Trusted Types policy and the namespace wrapper.
- Every render a chunk returns is a cloned node (rows, branches, child views, catch views, regions). Do not add an HTML-string path to `patchList`, `setBranch$`, `addChild` or `errors.ts`. Why: only `html=` content is parsed from a string, and each string path cost loader bytes (the todo loader went from 4073 to 4026 B when they went).
- Learn the server's state with a script `import()` (`skew.ts` imports `build.js`), not a `fetch`. Why: a strict CSP such as `default-src 'none'` blocks `fetch`. Put a check that runs only after a failure in a served file and import it then, since the loader pays for every byte on every page.
- A remount (`hot.ts`) replaces the root's `body` element, not its children. Why: `findNode` caches nodes by root.
- A chosen row binding runs on every kept row, even when the row's item is the same reference. Why: a path under `<list>.*` may read another item (`rows[i]`, a `find` over the list), not the row's own, and the manifest cannot tell the two apart; skipping such rows showed stale text (`perf-list-kept`, tests in `test/client/list/kept-rows.test.ts`). Skipping needs a compiler mark for bindings that read only their own item.
- A row keeps the nodes of its last walk on its start marker (`rowNodes`) with the block count of that walk (`addCount` in `patch/blocks.ts`), and is walked again only when a block was added since. Why: every branch swap and region swap adds its block through the hooks, and a binding absent from an inactive branch must not cost a walk per lookup. Code that changes a row's markup must call `addBlock`.
- A row is a cloned fragment that starts with its `<!--i-->` and ends with its `<!--/i-->` marker; `patchList` takes the first and last node as the row's range without checking. Why: the check cost loader bytes, and the compiler's templates always hold both markers.
- Register a loader hook that does nothing for blocks inside rows with the internal `onPageBlock`, not `onBlock`. Why: removed rows are walked for blocks only while some hook may act inside rows (`rowHooks`), and the walk was 1.4 ms of a clear of 1,000 rows. The nesting, head and subs hooks register with `onBlock`, so apps with those flags still walk removed rows.
- Tests never wait a fixed time. Use `settled()` and `until` from `idlip/testing`. Why: tests under load failed twice on a fixed wait (`fix-flaky-tests`, `fix-flaky-tests-2`). The title update of `<Head>` is one tick after `settled()`.
