# compiler

- A bound value of a URL attribute is wrapped in `safeUrl$` (`core/helpers.ts`), decided by `getUrlKind(tag, name, target)` in `core/url.ts`. A new URL attribute goes in `URL_ATTRS`, a new element-specific case (a frame, an animation target) in `getUrlKind`. Why: the compiler wraps only the listed names, and a value a browser runs as a script or a document must not come from data. A literal in source is not wrapped, since the author wrote it.
- Raw HTML reaches the page only through `trusted(...)` imported from `idlip`: `html=` and a bound `srcdoc`. Anything else is `html-trusted` or `srcdoc-trusted`. Why: `trusted` is the one place the author vouches for markup.
- A chunk imports its runtime helpers from `idlip/helpers` (`HELPERS_MODULE`), never a copy. The Vite plugin serves that module from `printHelpersModule()`, and the loader loads it with the first chunk (`helpers` in the chunk map). Why: copies put the same helpers in every chunk (dashboard dist 150.4 kB gzip with copies, 104.0 kB with the shared module), and the loader's parallel load keeps the first click one round trip.
- A helper of `idlip/helpers` (`core/helpers.ts`, `core/dynamic.ts`) holds no comment in its body and no name from outside its own text. Why: `printHelpersModule` writes the module from each function's `toString()`.
- A chunk imports a child's view by name (`import { init as $init_Row, render as $render_Row }`), not as a namespace. Why: the view is also an entry, and a namespace import made the bundler emit each view twice (an entry that re-exports a second file).
- A helper ends in `$` (`setAttr$`, `safeUrl$`, `track$`, `getRows$`) and is listed in `HELPER_NAMES`. A module-level author name equal to one is `module-reserved-name`. A local that generated code declares starts with `$` (`$after`, `$e`, `dynamic$`, `lists$` and the cloned templates `template<kind><id>$`, such as `templateL3$` and `templateC4_0$`, are the module-level exceptions that end in `$`). Why: a generated name must not collide with the author's.
- Region, block and boundary ids count on their own counter (`e` regions from 0), so adding a `<Try>` does not move the ids of lists, conditions or events after it. Why: golden fixtures and chunk names depend on ids.
- A change to a chunk's exports rewrites the goldens (`UPDATE_TRY=1 pnpm vitest run test/try`, and the fixture tests). Why: goldens compare the whole chunk.
- A client row or branch with at least one write clones a template (`view/codegen/template.ts`, `clone$` in `core/helpers.ts`). The clone must hold the nodes the HTML would parse to, markers included. A block inside a body is a marked comment (`<!--c<id>:x<n>-->`, `<!--/lx<n>-->`), and the body's writes clone the block's templates next to it. A new node kind in a cloned body needs a write that matches the HTML, and a differential subject (`cloned`, `nested-blocks`). Why: the patcher, `readRows` and the differential test read cloned and server rows alike. Create 1,000 rows went from 15.0 to 7.2 ms of script.
- A body with no write renders HTML. Why: the template and the clone calls cost more bytes in the chunk than the parse of a static body saves.
- A component other than the main one (the default export) has the module id `<file>#<Name>` and a module record `$<Name>` (`manifest`, `chunks`, `uses`, `default`) in the server module. `selectComponents` (`view/codegen/components.ts`) picks the components. Why: the default export keeps the chunk names of a one-component file, and a parent imports a named child by its record.
