# 0001: The idlip DSL

Status: draft. [0002](0002-modules.md) replaces the Messages, Update and Nesting sections.

idlip is a resumable UI framework built on Model-View-Update (MVU). The server renders the page and writes the model and the messages into the HTML. The client continues from that state on the first event, without running the view again.

idlip keeps the MVU concept and does not copy Elm's API. A name or shape from Elm stays only when it fits TypeScript and resumability.

## Rule

Nothing the client must resume can be a closure. The model, messages, commands and subscriptions are plain data. The view and update are pure functions that the compiler splits into chunks.

## Messages

A message is a tag and a payload. The spec exists only as a type. Tags are camelCase, so constructor calls read as function calls. A tag with no payload has the type `undefined`.

```ts
import { defineMessages } from 'idlip';

export const msg = defineMessages<{
  add: undefined;
  setDraft: string;
  toggle: { id: string };
  remove: { id: string };
}>();

// msg.toggle({ id }) returns { t: 'toggle', p: { id } }
// In the HTML: on:click='["toggle",{"id":"a1"}]'
```

## Model

The model is one immutable value that serializes. Functions, class instances and DOM nodes are not allowed. `Date`, `Map`, `Set` and `bigint` go through seroval.

```ts
export interface Model {
  draft: string;
  todos: Todo[];
  filter: 'all' | 'active' | 'done';
}
```

## Update

Update is an object keyed by message tag. Each key is a split point, so the compiler emits one chunk per handler. A handler returns the next model, or the next model and a command.

```ts
export const update = defineUpdate<Model, typeof msg>({
  add(m) {
    const todo = { id: createId(), text: m.draft, done: false };
    return { ...m, draft: '', todos: [...m.todos, todo] };
  },
  setDraft(m, text) {
    return { ...m, draft: text };
  },
});
```

## View

The view is JSX with rules the compiler enforces:

| Construct      | Rule                                                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Hole `{expr}`  | A pure expression over the model, loop variables and literals. The compiler records the model paths it reads.            |
| Helper call    | Depends on the paths of its arguments. Passing the whole model is a warning.                                             |
| Event `on:*`   | A message constructor call. The payload holds literals, loop variable paths or `$event.*`. A closure is a compile error. |
| `$event.value` | A placeholder written as `["$event","value"]`. The runtime reads the value from the DOM event.                           |
| Lists          | `<For each key>` only, so the compiler can track item paths.                                                             |
| Conditions     | `<Show when>` or `<Switch>` and `<Match>`. Ternaries only for text and attributes.                                       |

```tsx
export function view(m: Model) {
  return (
    <main>
      <input value={m.draft} on:input={msg.setDraft($event.value)} />
      <button on:click={msg.add()} disabled={m.draft === ''}>
        Add
      </button>
      <For each={m.todos} key="id">
        {(t) => (
          <li class={{ done: t.done }}>
            <input type="checkbox" checked={t.done} on:click={msg.toggle({ id: t.id })} />
            {t.text}
          </li>
        )}
      </For>
    </main>
  );
}
```

## Patching after resume

The client has no virtual DOM to diff against after resume. Instead:

1. The compiler turns the view into templates with holes. Each hole binds to a set of model paths.
2. After update, the runtime compares the old and new model by reference along those paths.
3. The runtime loads only the bindings whose paths changed, and patches their DOM nodes.

Bindings with the same path set share one chunk.

## Commands and subscriptions

Both are data. A command names the message tag that receives its result.

```ts
Http.get('/todos', 'gotTodos');

export function subscriptions(m: Model): Sub[] {
  return [m.timerOn && Time.every(1000, 'tick')];
}
```

The server writes the list of active subscriptions into the HTML. The client starts only those on resume.

## Nesting

A child module gets a message prefix instead of a mapping function.

```tsx
<Counter model={m.left} as="left" />
```

DOM messages become `["left","increment"]`. The parent update routes them with a static table entry from `nest('left', 'left', Counter.update)`.

## Compiler output

For each module, the compiler (an oxc pass) emits:

- a server renderer
- one chunk per update handler
- one chunk per binding group
- a manifest from message tags and model paths to chunks

## Open questions

- JSX or a tagged template. Leaning JSX, for the oxc parser and TypeScript checks.
- Spread updates or a compile-time draft rewrite. Spread first, since diffs stay reference-based.
- `$event` placeholders or decoders. Placeholders first.
- How events that fire before their chunk loads are queued and replayed.

## Prior art

- Qwik and Marko 6 are resumable, built on signals.
- elm-pages and Lustre render on the server and hydrate.
- brumate is the author's resumable component language.
