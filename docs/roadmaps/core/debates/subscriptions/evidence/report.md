# Debate: Decide how idlip components declare subscriptions (timers, sockets, custom async sources, window and document events) under the no-compile-time-API and no-implicit-state-machine rules

## Settled structure

- P1: Keep option A as the one general form: <Subscribe to={source} input={v} on:value={h}> rendered under a condition on an explicit state union (clock.state === 'running'). Start and stop are the block's mount and unmount, so the lifecycle is a visible expression and no handle is stored. (1 new block component, 0 new compile-time imports)
- P2: Change one rule in A: input is read once at start, and a new run needs a new key (<Subscribe key={clock.ms} ...>) or a remount through the condition. The runtime never compares old and new input. This removes the only implicit diff in the draft ('when input changes, the runtime stops the old run'), which J4 forbids. (0 runtime input comparisons)
  - amended by P6: Amend P2, P3, P4 to the upheld costs: (a) the compiler rejects a Subscribe `input` that reads state unless `key` reads the same state (O3); (b) stock sources with several parameters take one input object, e.g. socket({url, protocols}) (O2); (c) the serializability check runs at dispatch in dev builds, not at compile time (O1).
- P3: Ship order: (1) <window> and <document> intrinsics, delegated by the loader, with no source and no marker; (2) Subscribe with server-rendered markers and loader start and stop; (3) stock sources as plain module-level async generators (Time.every, WebSocket, EventSource, media query). Step 1 covers keydown, resize, online and visibilitychange, which are the most common cases, and does not wait for step 2. (3 steps, step 1 about a third of the work)

- P4: Each value a source yields is dispatched as an ordinary message on:value with the value as its serialized payload, so the message log records it and devtools replay never re-runs the source. - P5: Resume cost stays at zero for pages without subscriptions: the server renders one marker per active Subscribe (source chunk id plus serialized input), and the loader loads the source chunk only when the marker is in the page. Closing the page state (condition false) leaves no marker, so a resumed page never restarts a stopped source. (0 bytes of JS on pages with no subscription)
- P7: Answer O5 with pull-based delivery, no new policy object: the loader calls next() on a source only after the handler's message has patched, so one value per subscription is in flight and a source cannot flood the queue; the source decides what to drop. Stock Time.every yields the latest tick and skips missed ones; the socket source holds a bounded buffer (default 100) and drops oldest. For push events on <window>/<document> (resize, pointermove, scroll), the loader keeps one pending message per element and event name and replaces it with the newest until dispatch (latest-wins). The dev message log is a ring of 1000 entries. (1 in-flight message per subscription)
- P10: Sequence around O4: P3 step 1 (<window>/<document> intrinsics) ships first in commands-subs with no block hook. Subscribe (P3 step 2) is marked dependent on the block add/remove hook that <Head> and <Try> already need (J11), and the hook contract (start on add, stop on remove, children before parents, For rows from the item template, HMR remove) is added to compiled-format once by the Head/Try node, not by commands-subs. If that hook is late, commands-subs delivers step 1 and the stock-source part of step 3 as a runtime-only Subscribe on top-level blocks, and defers nested and For cases. (2 steps shipped before the hook)
- P11: Answer O7: delivery stops at once, cleanup is bounded by the source. On block removal the runtime aborts the signal, calls return() without awaiting it, and discards any value the generator yields afterwards, so no handler runs after the block is gone. A finally block runs promptly only if the source ends its awaits on the signal. Stock sources (Time.every, socket, EventSource, media query) do, by construction. For custom sources the author writes `await until(signal, promise)` or `Time.sleep(ms, signal)`, both plain runtime imports that reject on abort. In dev builds the runtime warns, naming the source, if return() has not settled 1000 ms after abort. There is no static check, and the proposal does not claim one. (0 handlers run after block removal)
- P12: Answer O8: on <window>, <document> and any element, delivery queues every event by default and keeps each event's value, as compiled-format line 36 requires. Latest-wins is opt-in in the source through the `latest:` attribute namespace, as in <window latest:pointermove={move} on:keydown={key} />. The author sees the policy next to the handler, and the loader has no per-event table. This replaces P7's hidden latest-wins rule for push events. P7's pull-based rule for Subscribe sources stays. (0 hidden per-event policies)
- P13: Answer O9: the dev log is a ring of 1000 messages, each with its recorded model (already kept per J13). Replay starts from the oldest kept snapshot and reports 'replay window: last N messages'; it does not promise replay from page load. A fast source can shrink the window to seconds, so a source meant for replay should yield at a lower rate or the author uses latest: for push events. Production keeps no log. (1000 messages kept in dev)
- P14: Answer O11: the block add/remove hook is owned by patch-bindings (it owns packages/idlip/src/client/patch/** and patches condition blocks), declared once in compiled-format. patch-lists calls it for For rows through the existing patchList interface, document-head and errors call it for head blocks and the Try region swap, and commands-subs only registers start and stop on it. This needs the errors -> commands-subs edge removed (J12), which removes the cycle. I drop P10's fallback of a runtime-only Subscribe on top-level blocks, since it cannot stop. (1 contract section in compiled-format)

## Rejected

- A1: Cheaper in scope than A for timers: no new construct. A self-scheduling handler, async function tick() { if (clock.state !== 'running') return; await Time.sleep(1000); tick(); }, reuses await and the explicit union; the pending sleep cannot be cancelled but only wakes a handler that exits. It covers timers only; sockets, EventSource and custom sources still need P1, and window and document events still need P3 step 1. Option B (for await in a handler) is dearer than this because it reverses the 'no await in loops' rule, leaves a quiet socket open after the stop state, and needs a task handle for abort.. Why not: O6: a page resumed in the running state has no pending sleep, so the timer never restarts; and it covers timers only. (by O6, P8, P15)
- A2: Cut v1 to what has no open contract: window and document intrinsics (P3 step 1) plus Subscribe limited to stock sources that live in the runtime core like Time and Random (timer, WebSocket, EventSource, media query), each with a fixed typed signature. That needs no source chunk id, no marker for user generators, no serializability analysis (O1) and no wrapper typing (O2). User-defined async generators then join as a later step once the block lifecycle hook (O4) is settled. Same explicit-union lifecycle, same rule set; delivers the listed use cases except custom sources.. Why not: Stock-source Subscribe still starts and stops with blocks, so it still needs O4's hook (J11); it drops custom sources, which the goal names, to save O1 and O2, which are small after their rulings.
