# Log: render-stream

- Read brumate `renderToStream`/`streamParts`: both go through one `partsStream` that writes the first render whole, then the pending chunks, and `cancel` aborts the request.
- First design (dropped): the opening chunk (doctype, listener, loader script) went out before the render, with a `setImmediate` yield so the reader could write it. It cost 9% of dashboard SSR throughput (4,650 to 4,215 renders/s), 3% without the yield.
- Decision from the user (2026-11-23, relayed by the coordinator): follow brumate's split. The first chunk is the whole first render (head, body, state). idlip renders synchronously, so an early head gains nothing. This replaces the brief's line about flushing the head before the body. The yield is gone.
- Design: one `createStream` with an explicit phase union (`first`, `pending`, `done`), one chunk per pull. A render error in `first` fails the stream before it sends a byte. `renderSync` is exported from `render.ts` for it (not from the index).
- `RenderResult.pending: AsyncIterable<string>` is the hook for `stream-model`. `renderPage` returns the shared empty `NOTHING_PENDING`; the stream closes in the first chunk when it sees it. `cancel` calls `return()` on the pending iterator, so the work stops in the generator's `finally`. Change request: `contracts/core-api-render-stream.change-request.md`.
- `render()` keeps returning the body string: it has many callers (tests, fixtures, entries, the website). `renderPage` is the equivalent of brumate's `render`, which returns the parts plus `pending`. Left for the coordinator to decide.
- Dashboard SSR (`benchmarks/harness/ssr-ab.mjs dashboard speed`, 1.5 s, 3 runs, Apple M2): `renderPage` + string concat 4695, 4737, 4518 renders/s. `renderToStream` read to a string: 4685, 4575, 4398. Within noise.
- Benchmarks and examples are `entry-setup`'s paths. I measured with a temporary dashboard entry and reverted it.
- Review fixes: `cancel` hung when a `next()` was in flight, since `return()` queues behind it. `RenderResult` gets `signal` (lazy `AbortController`) and `abort()`; `cancel` aborts, then calls `return()` without awaiting. Test with a generator stuck on the signal. Dropped `StreamOptions.head` (string-built shell). The pending iterator resolves before the first enqueue. `cancel` sets `done` once, and `pull` has no `done` case. Docs say `pending` is single-use and the render happens at construction.
